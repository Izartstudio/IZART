# Izart production-readiness audit

Audit of the local working tree, November 23, 2026. The working tree already includes changes beyond HEAD. Use this state as the comparison baseline. Implementation requires approval. This audit does not assert that the site meets its performance or compatibility targets.

## Architecture and scope

- **Runtime.** Node 22.19.0 locally, Next.js 16.3.5 App Router and Turbopack, React and React DOM 19.2.8, TypeScript 6.0.3, ESLint 9.39.5, Three.js 0.186.0, GSAP 3.15.1, Sanity 6.15.0 with client 8.6.2, and Sharp 0.35.4. Versions are from the lockfile.
- **Routes.** Server pages compose feature components for Home, Industries, Services and their service details, Portfolio and case studies, Careers and job details, Blogs and articles, Manifesto, Playground, and preserved author routes. The legacy catch-all resolves registered service subpages and preserved content. Contact, careers applications, and playground audio use route handlers.
- **Data.** Most pages are prerendered or generated with revalidation. Blogs index is dynamic in the local build. Sanity queries populate server pages, often with bundled fallback data. Route-level components pass serializable content to client enhancements. Portfolio consumes Sanity projects and server-derived image palettes.
- **UI and motion.** Global navigation is mounted in the root layout. Shared components cover showcase cards, controls, forms, dark green labels and footer artifacts. Styling combines a large global stylesheet, feature CSS modules and JS-controlled custom properties. Scroll is native, with sticky layouts, RAF-driven section effects, pointer parallax, CSS and Web Animations, and separate WebGL stages. No Lenis or ScrollTrigger integration was found in application source. The GSAP ticker/timeline usage is in the services mosaic.
- **Responsive and loading model.** The site uses intrinsic image sizes, viewport units, CSS Grid/Flexbox and breakpoint-specific assets. Next Image handles many images, while parts of the gallery, WebGL, and the footer take alternative paths. Responsive and reduced-motion decisions are split between CSS and client media queries.
- **State and visibility.** React owns selection and interaction state. Effects own scroll listeners, observer lifecycles, transforms, animation handles and WebGL resources. The tunnel, contact shader, footer cycle and gallery already contain visibility or cleanup logic worth preserving.

## Baseline and validation limits

- Production build completed, including TypeScript and generation of 103 static pages. Standalone typecheck and the crawler policy test passed. The service fan test passed its geometry, reduced motion and lifecycle cases.
- Default full lint failed with V8 heap exhaustion near its effective 2 GB limit. About theme, gallery lifecycle, services showcase and showcase progress tests failed at their render/import harnesses. Those failures limit confidence and do not by themselves establish production UI defects.
- Local asset footprint is about 178 MB in `public/assets`. The build emitted 30 JavaScript chunk files and approximately 1.9 MB in `.next/static` on disk. These are artifact measurements, not per-route download sizes or compressed transfer weights.
- Production HTTP smoke checks returned 200 for 14 representative routes, including Home, Industries, Services and a detail page, the Portfolio and Benicio, Blogs, Careers and a job detail, Manifesto, Playground and Authors. The six unresolved menu paths returned 404.
- Chromium 158 headless smoke sweep covered nine routes (Home, Industries, Services, Brand Identity, Portfolio, Careers, Blogs, Playground and Manifesto) at 320, 375, 430, 600, 767, 768, 991, 992, 1024, 1280, 1440, 1728 and 1920 px, all at 900 px height. The sweep found no document-level horizontal overflow beyond 1 px and no uncaught page exceptions during sampling. It did not exercise every scroll state, viewport height, route detail or console warning.
- No post-change results exist. Core Web Vitals release targets remain LCP ≤ 2.5 s, INP ≤ 200 ms and CLS ≤ 0.1. A lab result is not field data. Record cold and warm transfers, LCP and CLS, interaction timings during real flows, long tasks and frame timing before claiming improvement.
- Browser geometry sweeps are a screening check, not visual or interaction sign-off. Full touch, trackpad, focused controls, real Safari/WebKit and Firefox, GPU acceleration behavior, WebGL fallback/context-loss, reduced motion, slow connections and webhook delivery remain release verification items. Do not submit live enquiries as part of a test.

## Proposed implementation sequence

1. **Establish a stable release baseline.** Restore lint and component checks, run the local production route/link inventory, verify deployment indexing configuration and confirm navigation destinations and webhook test contract. Resolve release blockers in small changes.
2. **Fix interaction and layout by section.** Start with Explore and menu lock/focus, then project rails/cards, process and services, and the showreel. Capture before/after at 320, 375, 430, 600, 768, 1024, 1280, 1440, 1728 and 1920 px, with additional widths around the 767/768 and 991/992 boundaries and short, tall and landscape heights.
3. **Optimize the measured critical path.** Compare preview vs published asset waterfalls, resize the expensive media, stage video/texture loads, then profile render loops and showreel layout. Verify comparison screenshots and first-hover/first-scroll readiness.
4. **Refactor only proven duplication and fragile lifecycle code.** Keep App Router and CMS structure. Share meaningful utilities after functional parity, and remove orphaned code/assets only after dependency and reference checks.
5. **Validate and report.** Run checks and a clean build, test navigation/forms and scroll/animation with supported browsers, remeasure with comparable conditions, and record files changed, issues resolved and remaining limitations.

Highest regression risk is concentrated in Explore and sticky scroll geometry, the full-frame video transition, and media lifecycle changes. Each changes how assets or elements enter and leave the viewport. Land them separately with screenshots, route-change and reverse-scroll checks. Media encoding and webhook acknowledgement also require their own visual and contract checks respectively.

## Pass 1 · Showreel scroll layout

**Status.** Track A showreel rendering addressed in part on `codex/production-readiness-pass-1`. The existing working tree was carried onto the branch. This pass changes the home showreel’s CSS and adds a browser regression check. All other findings above remain open, including Track B, navbar destinations, contact delivery, full lint, component harnesses and SEO decisions.

**Root cause and fix.** The scroll handler already computes a continuous trajectory and scales the running iframe. Its width and height variables also resized the visible frame on every scroll sample, forcing layout in addition to compositing. The CSS now translates a fixed-size surface and clips it to the same visible rectangle. The player's transform follows the center of that rectangle. The same JS geometry, iframe sources, playback ownership, reduced-motion threshold and section heights are used.

**Reproduce.** Build with `npm run build` and start with `npm run start -- --hostname 127.0.0.1 --port 3100`. Run `SHOWREEL_REPORT=/tmp/izart-showreel node scripts/test-showreel-motion.mjs`. Use `PERF_BASE_URL` for a different local port and `CHROME_PATH` for a non-default Chrome installation. Run the same script against the preserved pre-pass source and the updated source with the same Sanity content. The harness uses a deterministic stripe fixture in the Vimeo iframe and captures three screenshots per viewport plus a JSON report. It sweeps 25 forward and 25 reverse steps at each viewport, resizes between runs, checks the Explore handoff and return lock, then navigates to Industries and checks that the last project tick drives the marker to the end within a 1% tolerance. Baseline and post-change artifacts were saved under `/tmp/izart-showreel-before` and `/tmp/izart-showreel-after`.

| Chromium 158 headless viewport | Layout events before → after | Cumulative page layout time before → after |
|---|---:|---:|
| 1440×900 | 92 → 52 | 8.55 → 7.05 ms |
| 430×740 | 112 → 61 | 7.84 → 4.64 ms |
| 1024×560 | 92 → 44 | 8.33 → 5.41 ms |

One run per condition. Counts and durations cover the whole page during scripted scroll and may vary with asynchronous work. The data supports lower layout activity in this test. It does not establish a change in real-device frame rates, INP or GPU compositing cost.

**Visual and functional checks.** All 150 sampled geometry tuples matched exactly across builds. Expansion reached viewport dimensions and reversed at all three sizes. Compared nine screenshot pairs. Full-size captures had no pixel differences above a 15/255 RGB channel threshold. The largest whole-frame change was 2.53% of pixels above this threshold at the 1024 px midpoint. Images include independently animated UI and headless compositing, so this is a comparison rather than a pixel-identical sign-off. The mobile midpoint screenshots show the growing frame overlapping the last stats row in both versions. This existing behavior needs a separate choreography decision. Explore landed at the showcase and restored the scroll lock on return. The Industries showcase had seven cards and seven ticks, and its last tick reached the final marker range. No uncaught page exceptions were observed in either run. Both production builds passed with the configured Sanity connection. Targeted ESLint and whitespace checks passed.

**Files.** `src/app/globals.css`, `scripts/test-showreel-motion.mjs`, and this audit.

**Next review.** Validate the real Vimeo player and touch scrolling in Safari/WebKit and Chromium on devices, then check Firefox and reduced motion. Investigate the mobile stats overlap and profile Explore interruptions independently. The test uses scripted scrolling and a fixture, so real media playback, dropped frames and touch inertia remain unverified. The release issues retain their audit status and require their own passes. Keep intentional navigation and SEO destinations pending confirmation. No live contact submissions were sent.
